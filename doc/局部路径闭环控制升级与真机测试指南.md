# 局部路径闭环控制升级与真机测试指南

> **坐标接口更新：** 本文的控制算法说明仍有效；其中旧
> `/body_state_estimation_global`、`lio_map` 示例已由
> `/omni/tf_manager/body_odom_global`、`omni_map` 和 manager `ready` 门控取代。

本文对应 ROS 2 分支中“局部 B-spline → `cmd_vel`”链路的本轮升级。目标不是单纯把 Pure Pursuit 调得更激进，而是先统一真实执行进度、补齐失联停车和速度能力约束，再让动态障碍响应可以安全调快。

> 重要：源码已经按真机安全链整理，但当前开发机没有 ROS 2 Humble/colcon，不能替代 Orin 完成最终编译和执行测试。第一次测试必须吊起机器狗或保证四周完全空旷，并保留物理急停。

## 1. 本轮解决的问题

### 1.1 FSM 和控制器统一使用真实空间进度

旧实现中，控制器会按 odom 找最近点，但 FSM 的重规划和碰撞检查仍使用 `now - start_time`。规划轨迹按较高速度计时、真机实际走得较慢时，FSM 会把机器狗尚未经过的路径误认为已经执行完。

现在 FSM 和控制器都使用同一个 `LocalTrajectoryTracker` 算法：

1. 对局部 B-spline 按时间采样成空间折线；
2. 把机体 odom 单调投影到折线；
3. 用实际弧长映射回 B-spline 参数时间；
4. 用 movement credit 限制一次前跳，避免定位噪声、自交路径或静止状态误跳进度。

ALIGN 原地旋转时不再修改 `start_time`，空间进度会因机体没有平移而自然冻结。

### 1.2 近场动态障碍先停车，再重规划

安全检查以 20 Hz 运行，并从实际进度向后保留 `0.10 m` 扫描余量：

- 障碍位于 `fsm.emergency_time` 对应的近场范围内：先撤销运动授权、立即停车，停稳后再规划；
- 障碍较远：允许先重规划，成功后切换新轨迹；
- 重规划失败：进入 REPLAN；规划器长时间无响应时，控制器心跳看门狗会独立停车。

这关闭了旧实现中“先同步跑优化器，优化失败后才决定是否急停”的危险窗口。

另外增加了两项空间保护：

- 横向偏离局部 B-spline 超过阈值时停车重规划；
- 每个安全检查周期都检查“实机位置 → Pure Pursuit 前视点”的保守控制包络：裸 PP 圆弧、固定弦、TRACK 航向反馈、yaw 暂时关闭时的直行、SDK 最小角速度量化轨迹，以及 ALIGN/急弯准备时的原地旋转；机身 yaw 按不大于 `0.10 rad` 的步长扫过并交给双圆柱模型，避免原 B-spline 无碰撞但实际转向回切时撞角。

恢复包络和控制器共用同一组 launch 参数。通过 `controller_*` 修改前视距离、航向增益、死区或最小线角速度时，launch 会同步覆盖 FSM 的安全模型，避免“控制命令已经改变，碰撞预测仍用旧值”。

### 1.3 规划器心跳看门狗

新增 `/planning/planner_heartbeat`。运动授权同时核对：

- `motion_allowed`；
- `traj_id`；
- B-spline 不可变的 `trajectory_start_time`；
- 控制器本地 steady clock 接收超时。

只比较 `traj_id` 不够，因为规划器重启后编号可能从 1 重新开始。任何心跳超时、禁止运动或双身份不匹配，控制器都会绕过滤波立即发布零速度。B-spline 可以继续缓存，匹配心跳恢复后会按当前 odom 重新投影，不会按旧时间盲走。

### 1.4 Pure Pursuit 速度治理

正常 TRACK 控制使用：

\[
\omega = v\kappa + k_\theta e_\theta
\]

并加入：

- TRACK/ALIGN 双阈值滞回；
- 航向误差连续降速；
- 曲率舒适限速；
- 横向加速度限速；
- 根据角速度能力反推允许线速度；
- 线加速度和减速度限制；
- 终点制动速度；
- 左右换向或角速度滤波尚未准备好时先停止平移；
- ALIGN 硬限制为零平移；
- ALIGN 增益接近退出阈值时连续过渡到 TRACK 增益。

角速度滤波后仍会再次约束实际可发布的 `vx`，避免急弯开始或左右换向时“线速度已经向前、角速度却还在错误方向”。
若急曲率使安全线速度低于 SDK 的 `0.05 m/s` 最小值，控制器会保持
`vx=0` 并先按曲率方向原地转向；几何曲率下降到可执行范围后，再走线角
同步起步流程，避免在终点附近或大横偏处永久输出 `0/0`。

曲率前馈与航向反馈反号时，角速度能力按 `vκ + w_heading` 的真实符号
计算；加速穿过零点时会先在弱 yaw 走廊等待新方向稳定，避免周期性
“走—停—走”。终点制动目标若落在 `(0, 0.05 m/s)` 且机器人仍在终点
容差外，会量化为一次最小爬行速度；进入容差后再按正常减速度停车。

### 1.5 输入和状态健壮性

控制器在构造 `UniformBspline` 前检查：

- 只接受三次 B-spline；
- 控制点、knot 数量严格匹配；
- 控制点和 knot 全部有限；
- knot 严格递增且差值不溢出；
- 时长和控制点数量不超过资源上限；
- 坐标系与 odom 一致；
- `start_time` 纳秒字段合法。

构造后还会采样检查位置、速度、加速度是否有限。坏轨迹不会再进入 Eigen 越界或让上一条轨迹继续执行。

## 2. 真机默认参数

真机脚本当前使用以下保守初值：

| 参数 | 默认值 | 作用 |
|---|---:|---|
| `CONTROLLER_PURE_PURSUIT_SPEED` | `0.20 m/s` | 正常巡航速度 |
| `CONTROLLER_MAX_VX` | `0.30 m/s` | 控制器最大前向速度 |
| `CONTROLLER_MAX_VYAW` | `0.50 rad/s` | 最大角速度 |
| `CONTROLLER_LOOKAHEAD_DIST` | `0.45 m` | Pure Pursuit 前视距离 |
| `CONTROLLER_HEADING_ERROR_THRESHOLD` | `0.80 rad` | 进入 ALIGN |
| `CONTROLLER_HEADING_ERROR_EXIT_THRESHOLD` | `0.45 rad` | 退出 ALIGN |
| `CONTROLLER_CURVATURE_SPEED_GAIN` | `0.60` | 曲率舒适降速强度 |
| `CONTROLLER_MAX_LATERAL_ACCELERATION` | `0.20 m/s²` | 转弯横向加速度上限 |
| `CONTROLLER_MAX_LINEAR_ACCELERATION` | `0.35 m/s²` | 正常线加速度上限 |
| `CONTROLLER_MAX_LINEAR_DECELERATION` | `0.60 m/s²` | 正常线减速度上限 |
| `CONTROLLER_YAW_START_THRESHOLD` | `0.06 rad/s` | raw 转向目标触发滞回的阈值 |
| `CONTROLLER_MIN_NONZERO_YAW_RATE` | `0.10 rad/s` | SDK 可执行的最小非零角速度 |
| `CONTROLLER_MIN_NONZERO_LINEAR_SPEED` | `0.05 m/s` | SDK 可执行的最小非零前向速度 |
| `CONTROLLER_YAW_SYNC_THRESHOLD` | `0.10 rad/s` | 达到该转向强度时线角同步起步 |
| `CONTROLLER_PLANNER_HEARTBEAT_TIMEOUT` | `0.40 s` | 规划器心跳超时 |
| `FSM_EMERGENCY_TIME` | `1.00 s` | 近场障碍急停窗口 |
| `FSM_LOCAL_PROGRESS_COLLISION_BACKTRACK` | `0.10 m` | 碰撞扫描后向余量 |
| `FSM_LOCAL_PROGRESS_MAX_CROSS_TRACK` | `0.40 m` | 最大横向偏差 |
| `FSM_LOCAL_RECOVERY_CHECK_MIN_CROSS_TRACK` | `0.05 m` | 日志中区分普通跟踪与明显偏离（不关闭检查） |
| `FSM_LOCAL_RECOVERY_LOOKAHEAD` | 跟随控制器前视距离 | 恢复扫掠的前视终点 |
| `FSM_LOCAL_FINISH_SPEED` | `0.06 m/s` | FSM 清轨迹前要求的实测末端速度 |
| `PLANNER_MAX_VEL` | `0.40 m/s` | 真机局部轨迹速度上限 |
| `PLANNER_MAX_ACC` | `0.50 m/s²` | 真机局部轨迹加速度上限 |

ZsiBot SDK/bridge 对小命令存在量化：默认 `|vx| < 0.05 m/s` 和 `|yaw| < 0.10 rad/s` 会被置零。因此最终下发端的 `0 ↔ 最小非零值` 跳变是硬件接口例外，不能理解为严格满足连续加速度。控制器内部已经对该约束做滞回，禁止在正负方向间直接跳变。

`fsm.local_recovery_sample_distance` 真机保持默认 `0.05 m`。调得更小会让
“中心位置 × 机身 yaw”的组合采样量急剧增加；极端横偏超过有界资源预算时，
系统会按安全策略停车，而不是静默跳过检查。

## 3. 在 Orin 上编译和测试

进入包含 `src/` 的工作空间：

```bash
cd /app/SCAN-Planner  # 按 Orin 上的实际工作空间路径调整
source /opt/ros/humble/setup.bash

# 必须先确认板端不是 1970 年；错误系统时间会让 Make 漏编，也会破坏 ROS/TF 时间戳。
date
timedatectl status

colcon build --symlink-install \
  --packages-up-to scan_planner \
  --cmake-args -DCMAKE_BUILD_TYPE=Release

source install/setup.bash
```

如果编译输出包含 `Clock skew detected`，先修正系统时间再重编。有网络时可启用 NTP：

```bash
sudo timedatectl set-ntp true
sudo systemctl restart systemd-timesyncd
timedatectl status
```

无网络时先用 `sudo timedatectl set-time 'YYYY-MM-DD HH:MM:SS'` 手动设置当前时间；
板端带 RTC 时再执行 `sudo hwclock --systohc` 持久化。

本轮新增了 ROS 消息。如果增量构建仍引用旧接口，可先单独清理 CMake 缓存后重建消息包：

```bash
colcon build --symlink-install \
  --packages-select scan_planner_msgs \
  --cmake-clean-cache

colcon build --symlink-install \
  --packages-up-to scan_planner \
  --cmake-args -DCMAKE_BUILD_TYPE=Release
```

运行测试：

```bash
colcon test --packages-select scan_planner
colcon test-result --verbose
```

确认新消息已生成：

```bash
source install/setup.bash
ros2 interface show scan_planner_msgs/msg/PlannerHeartbeat
```

任何编译错误或测试失败都应先处理，不能直接放下机器狗试跑。

## 4. 第一次启动：吊起或空旷场地

建议用更低的首测参数：

```bash
CONTROLLER_PURE_PURSUIT_SPEED=0.10 \
CONTROLLER_MAX_VX=0.15 \
CONTROLLER_MAX_VYAW=0.35 \
CONTROLLER_MAX_LINEAR_ACCELERATION=0.20 \
CONTROLLER_MAX_LINEAR_DECELERATION=0.40 \
PLANNER_MAX_VEL=0.30 \
FSM_EMERGENCY_TIME=1.20 \
tools/orin_runtime/run_real_planner.sh
```

该脚本默认只发布 `/scan_planner/cmd_vel`，由统一 robot bridge 接管；不会启动
旧 `zsibot_cmd_bridge`。

UDP proxy 模式把最后一行换成：

```bash
ENABLE_DEPRECATED_ZSIBOT_TRANSPORT=1 tools/orin_runtime/run_real_planner_udp.sh
```

另开终端检查：

```bash
source /opt/ros/humble/setup.bash
source /app/code/SCAN-Planner/install/setup.bash

ros2 topic hz /planning/planner_heartbeat
ros2 topic echo /planning/planner_heartbeat --once
ros2 topic echo /body_state_estimation_global --once
ros2 topic echo /scan_planner/cmd_vel
```

预期：

- heartbeat 约 `20 Hz`；
- WAIT_TARGET 时 `motion_allowed=false`；
- 有合法局部轨迹并进入执行状态后为 `true`；
- `traj_id` 和 `trajectory_start_time` 与 `/planning/bspline` 一致；
- body odom 的 `header.frame_id` 是 `lio_map`；
- 没有目标时 `cmd_vel` 始终为零。

## 5. 分阶段运动测试

### 5.1 直线与终点制动

先给前方约 `1 m` 的直线目标，确认：

- `linear.x` 从零缓慢上升；
- `angular.z` 在直线上为零或只做小量纠偏；
- 接近终点时先减速，不是从巡航速度一步归零；
- 停止位置允许有 `finish_dist` 量级误差，但不能在离终点很远处因轨迹时间结束而停车。

### 5.2 左右转和 ALIGN

分别给左前方、右前方目标：

- `angular.z > 0` 必须左转，`angular.z < 0` 必须右转；
- 大航向误差先停止平移再原地转向；
- 退出 ALIGN 后前向速度平缓恢复；
- 左右换向期间不允许继续以非零 `vx` 朝旧转向方向切弯。

若方向相反，立即停止，不要通过调增益掩盖 TF 或 SDK 符号错误。

### 5.3 心跳失联测试

此测试必须吊起机器狗。先查询进程 PID：

```bash
pgrep -af scan_planner_node
```

手工选择正确 PID 后暂停规划器：

```bash
kill -STOP <PID>
```

预期控制器在约 `CONTROLLER_PLANNER_HEARTBEAT_TIMEOUT` 内把 `/scan_planner/cmd_vel` 清零。随后恢复：

```bash
kill -CONT <PID>
```

如果整个控制器进程退出，bridge 自己的 `0.3 s` watchdog 应发送零速度。两个看门狗必须分别验证。

### 5.4 动态障碍测试

保持首测低速，让纸箱或软质挡板从路径侧面缓慢进入，不要让人直接站到机器狗正前方。

同时观察：

```bash
ros2 topic hz /cloud_registered_global
ros2 topic echo /planning/planner_heartbeat
ros2 topic echo /scan_planner/cmd_vel
```

在 RViz 中同时显示：

- `/grid_map/occupancy`；
- `/grid_map/occupancy_inflate`；
- `/planning/controller_bspline`；
- `/planning/controller_target`；
- `/body_state_estimation_global`。

预期行为：

- 障碍较远：生成绕行轨迹；
- 障碍进入近场窗口：heartbeat 先变为禁止，命令立即清零，停稳后再规划；
- 障碍移走后，必须等占据栅格被射线清空并成功生成新轨迹才恢复；
- Pure Pursuit 圆弧、弦及两者之间的恢复扫掠区有障碍时，不得直接切回路径。
- ALIGN、急弯原地准备和 TRACK 航向反馈对应的姿态/轨迹包络有障碍时，同样不得恢复运动。

当前代码对动态障碍采用“最新点云占据 + 高频碰撞检查”，没有做障碍速度预测。因此反应上限首先由点云频率、点云延迟和占据栅格更新决定；控制参数无法补救一条没有及时进入地图的障碍物。

## 6. 录包与判因

```bash
BODY_ODOM_TOPIC=/body_state_estimation_global \
OUTPUT_BAG=/tmp/scan_control_test \
tools/offline_validation/record_outputs.sh
```

默认录制集已经包含 `/planning/planner_heartbeat`。至少同时保留：

- 原始点云；
- `/grid_map/occupancy_inflate`；
- body odom；
- B-spline；
- heartbeat；
- controller target；
- `cmd_vel`。

停车时按以下顺序判因：

1. heartbeat 是否变为 false 或超时；
2. B-spline 双身份是否匹配；
3. odom 是否超过 `0.30 s` 未更新；
4. 是否进入 ALIGN；
5. 占据层是否命中轨迹或恢复扫掠区；
6. bridge 是否因 SDK 连接、站立状态或命令死区清零。

## 7. 常见调参方向

| 现象 | 优先检查/调整 |
|---|---|
| 动态障碍已经进入膨胀地图，但停车仍偏晚 | 增大 `FSM_EMERGENCY_TIME` 到 `1.2~1.5`；不要先提高车速 |
| 原始点云看见障碍，但 occupancy 没有 | 检查 frame、时间同步、`p_hit`、`p_occ` 和点云频率 |
| 障碍移走后长时间不恢复 | 检查射线清空、`p_miss`、`max_ray_length`，不要只减急停阈值 |
| 弯道切弯 | 降低巡航速度；增大 `CONTROLLER_CURVATURE_SPEED_GAIN`；降低最大横向加速度 |
| 转弯反应太迟 | 先确认 yaw 小命令没有被 SDK 死区清除，再小幅减小 yaw filter 时间常数或 start threshold |
| ALIGN/TRACK 来回抖 | 增大进入/退出阈值间隔，保持退出阈值明显小于进入阈值 |
| 定位跳变后直切回路径 | 减小最大 cross-track；检查恢复扫掠日志和 LIO 稳定性 |
| 正常规划时周期性停顿 | 测量 Orin 最坏规划耗时；确认是否超过 heartbeat timeout，再谨慎从 `0.40` 增至 `0.60 s` |
| 轨迹仍显得比真机动力学激进 | 把 `PLANNER_MAX_VEL` 降到 `0.30~0.35`，并同步降低 `PLANNER_MAX_ACC` |

不要把 heartbeat timeout 调到很大来掩盖规划器卡顿。它是最后一道独立停车保护。
